# MenuSidebar

The native half of the shared Sidebar.dsx adapter has no Web renderer: the slide-over panel, its scrim and its rows are composed by SwiftUI on Apple and by Material 3 ModalNavigationDrawer on Android, and a web build authors its own navigation in markup instead.

This element is web unsupported by DESIGN, not by omission: its essence is a vendor or platform runtime the web renderer does not ship, and its facet fills the tag only when its module is registered. It is named here rather than left off the list, because a library that quietly omits its own rows is not a library.

The native half of the shared Sidebar.dsx adapter has no Web renderer: the slide-over panel, its scrim and its rows are composed by SwiftUI on Apple and by Material 3 ModalNavigationDrawer on Android, and a web build authors its own navigation in markup instead.

**Known limits on the web**

- No DOM lookalike of the native drawer is mounted, so nothing here is reported as a functional slide-over menu.
- The census row records what already ships on the two native lanes; it grants the Web renderer nothing.

**Fallback.** Mounts the honest dsx-unsupported placeholder, a labelled marker carrying the `<MenuSidebar>` name and the dsx-unsupported class; never blank, never a fake lookalike of the native drawer.

**Implementation notes.** The native half of the shared Sidebar.dsx adapter. iOS has no system drawer primitive, so the panel is composed from real SwiftUI Button and List controls and is capped at min(320, width - 56); Android hands the whole drawer, scrim, gestures, back handling and touch targets to Material 3 ModalNavigationDrawer, so the two lanes agree on the attribute contract and not on the chrome.

Declared platforms: `ios`, `android`.
